# Project Workflow Template

> This workflow is used as the standard implementation process for every deliverable within the **SharePoint – Pathways to Possibilities** project.

---

# Workflow Overview

Every deliverable follows the same structured lifecycle to ensure consistency, maintainability, and clear documentation.

```text
Business Need
        │
        ▼
Planning
        │
        ▼
Design
        │
        ▼
Implementation
        │
        ▼
Testing
        │
        ▼
Documentation
        │
        ▼
Stakeholder Review
        │
        ▼
Revision (if required)
        │
        ▼
Completed Deliverable
```

---

# Phase 1 — Business Need

## Purpose

Identify the problem the deliverable is intended to solve.

### Activities

- Meet with stakeholders.
- Gather project requirements.
- Identify users.
- Define business goals.
- Clarify expected outcomes.

### Deliverables

- Business requirements
- Stakeholder expectations

---

# Phase 2 — Planning

## Purpose

Plan how the solution will be built.

### Activities

- Determine required form fields.
- Plan document structure.
- Identify dependencies.
- Estimate implementation effort.
- Create implementation plan.

### Deliverables

- Planning.md
- Requirements
- Initial design notes

---

# Phase 3 — Design

## Purpose

Create a user-friendly solution before implementation begins.

### Activities

- Organize sections logically.
- Group related questions.
- Reduce unnecessary fields.
- Improve user experience.
- Apply approved branding.

### Deliverables

- Form design
- Layout decisions
- Branding decisions

---

# Phase 4 — Implementation

## Purpose

Build the solution within Submittable or SharePoint.

### Activities

- Create the form.
- Configure required fields.
- Configure optional fields.
- Apply conditional logic (when needed).
- Add instructions.
- Apply branding.
- Configure notifications.
- Save implementation screenshots.

### Deliverables

- Completed solution
- Implementation.md

---

# Phase 5 — Testing

## Purpose

Verify that the solution works as expected.

### Activities

- Test required fields.
- Test optional fields.
- Verify conditional logic.
- Verify uploads.
- Test links.
- Test mobile layout.
- Test desktop layout.

### Deliverables

- Testing.md
- Screenshots

---

# Phase 6 — Documentation

## Purpose

Document the complete implementation process.

### Activities

- Update README.
- Document planning decisions.
- Document implementation steps.
- Record testing results.
- Capture lessons learned.

### Deliverables

- README.md
- Planning.md
- Decisions.md
- Implementation.md
- Testing.md

---

# Phase 7 — Stakeholder Review

## Purpose

Present the completed deliverable for review.

### Activities

- Demonstrate the solution.
- Gather committee feedback.
- Record requested changes.
- Update project roadmap if needed.

### Deliverables

- Meeting notes
- Revision list

---

# Phase 8 — Revision

## Purpose

Incorporate stakeholder feedback before final approval.

### Activities

- Make approved changes.
- Retest functionality.
- Update documentation.
- Capture new screenshots if necessary.

### Deliverables

- Final version
- Updated documentation

---

# Completion Criteria

A deliverable is considered complete when:

- Business requirements have been met.
- The solution has been implemented.
- Testing has been completed successfully.
- Documentation is complete.
- Stakeholder feedback has been addressed.
- The deliverable is approved for use.

---

# Documentation Produced

Each completed deliverable should include:

- README.md
- Planning.md
- Decisions.md
- Implementation.md
- Testing.md
- Screenshots

# Notes

This workflow serves as the standard implementation methodology for all deliverables in the **SharePoint – Pathways to Possibilities** repository.
